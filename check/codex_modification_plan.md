M01–M03 establish the contract. M04–M06 establish the unpaired baseline algorithms; M07–M08 establish paired distillation. M09–M10 complete runnable, comparable experiments. An implementation can sequence these in another order only if their dependencies and acceptance checks remain explicit.

**Loss and gradient acceptance tests.** These test scientific behavior rather than reproducing an implementation line for line.

1. Hand-constructed categorical distributions distinguish forward KL, reverse KL and weighted JS. KD soft-target CE and forward KL must have equal student gradients but their expected entropy offset in loss values. At T=1 this should match the archived functions to floating-point tolerance.
2. ABKD reduces to forward KL for alpha=1,beta=0 and reverse KL for alpha=0,beta=1; equal distributions give approximately zero; other zero-parameter/zero-sum limits are finite. Compare values and gradients to a high-precision reference away from singularities. Empty masks must follow the documented skip/error rule.
3. On `[prompt_a, prompt_b, response_c, response_d, EOS]`, train on predictions after prompt_b, response_c and response_d. Changing masked prompt/pad labels does not change loss. The first answer and genuine EOS both contribute; there is no prediction past the last target. Test left/right padding, batch lengths and truncated prompts.
4. After one update, at least one intended student parameter changes with finite gradients; teacher parameters and gradients do not. This must run through the actual training loop, including SKD, checkpointing, mixed precision and the selected optimizer.
5. A full-vocabulary chunked loss must match unchunked values and gradients. Test across small chunks, uneven valid-token counts and accumulation. Disallow top-k probability approximations in the primary losses.
6. DistiLLM-2's migrated fixed-pair loss/gradient must match the archived implementation with released defaults on small tensors. Test chosen/rejected order, skew directions, the detached branch, pair normalization and weighting schedule flags independently.

**Sampling acceptance tests.** Fixed seeds and controlled logits make algorithmic mistakes visible without large checkpoints.

1. GKD: mixture probability 0 always uses references; 1 always produces fresh student responses; 0.5 approaches its expected frequency on enough controlled draws. Changing student weights affects subsequent on-policy samples. Replay is absent in the primary path.
2. SKD: cover acceptance at teacher k=1 and k=full-vocabulary, rejection at the first/middle/last proposal, EOS in an accepted block, all proposals accepted, output budget exhaustion and repeated-cache updates. Acceptance decisions must inspect the exact IDs appended to the sequence.
3. Separate teacher and student distributions in a test so swapped/inherited temperature or top-p is detectable. Compare the optimized cached sampler to a slow reference on deterministic cases and compare empirical distribution/acceptance statistics on stochastic cases. Do not require identical RNG streams across optimized and scalar implementations unless explicitly designed.
4. Unwrapped one-process models and DDP models both work; tests must not rely on every model having `.module`. Dict and tensor generation returns are normalized at one boundary.
5. Qwen3 non-thinking prompts match their full training prefixes, and stop at the intended end-of-turn IDs. A thinking run, if later added, has a distinct protocol and response budget. Llama base prompts work without a built-in chat template.

**Model and environment acceptance sequence.** Avoid downloading or launching full expensive experiments until cheaper gates pass.

1. On the intended Linux/GPU server, record OS, Python, torch build/CUDA, NVIDIA driver, GPU models/VRAM/count, installed wheel versions and package hashes. Run the full resolver/install and `pip check`; ensure the environment imports every baseline. Confirm no source file in installed Transformers has been replaced.
2. Use small randomly initialized Qwen3 and Llama configurations under the exact locked Transformers version for model loading, forward/backward, generation, save/reload and loss tests. This isolates API problems from large-model memory limits.
3. With authorized model access, retrieve only configs/tokenizers first. Compare teacher/student mappings and prompt templates; verify checkpoint revisions and head dimensions. The Qwen metadata audit here can be reused at the recorded revisions, but actual output-head checks still require loading weights.
4. Run one then several updates of **all 10 method/pair combinations** on a tiny, disjoint fixture dataset with actual checkpoints. For DistiLLM-2 prepare tiny teacher/student pairs; for GKD/SKD use current-student generation. Record finite losses, nonzero student gradients, unchanged teacher, peak VRAM and successful outputs.
5. Run a two-process smoke test for each sampler/trainer path, checking no rank hangs and correct valid-token reduction/optimizer-step counts. Test unequal response lengths. SKD's student/teacher placement and ZeRO's generation-time parameter gathering must be exercised, not inferred from a launch file.
6. Save and resume each training path at a fixed step; compare continuation learning rate, global step, sample provenance, RNG state and loss to an uninterrupted reference within the chosen deterministic tolerance. Check LoRA export separately only if that track is enabled.
7. Freeze dataset splits/metrics/budget, then run the primary five-method × two-pair matrix for seeds 42/43/44. This is 10 configurations and 30 seeded runs. Treat a changed model variant or resource stack as a new manifest version.
